## 1. 产品定义

Mirawind Library 是一个单用户、自托管的个人在线图书馆。它将异构电子书，尤其是 MinerU
输出包，以及后续支持的 EPUB，接纳为自有结构化正文 IR，再转换为统一、语义化、可搜索、
适合浏览器 AI 理解的网页图书。

产品不是 PDF/EPUB 文件浏览器，也不是博客系统。其核心价值是：

1. 将不同来源的图书统一转换为结构清晰的语义 HTML。
2. 以接近 `zh.d2l.ai` 的方式阅读章节化教材。
3. 提供完整书库管理、全文搜索和私人阅读状态。
4. 对公开图书提供可索引、可分享、可被浏览器 AI 理解的网页。
5. 保留原始文件作为可选附件，而不是将其作为主阅读载体。

## 2. 用户与权限模型

### 2.1 用户角色

系统只有两个访问身份：

- 匿名访客
- 唯一管理员

系统 `MUST NOT` 提供公开注册、多用户空间、社交关注、公开评论或协作编辑。

### 2.2 登录

管理员登录 `MUST` 使用：

- Passkey 作为主要方式
- 备用密码作为恢复方式
- 无注册入口

认证协议实现 `MUST` 复用成熟库，不自行实现 WebAuthn 验证流程。

首次管理员只能通过服务器终端的一次性离线命令创建。正式 Web 服务
`MUST NOT` 暴露注册、邀请或首次初始化入口。首次使用备用密码登录后，
管理员在已有 session 内登记 Passkey。

唯一管理员最多登记 10 个可命名 Passkey。新增、重命名和删除必须具有
有效 session，并且最近一次服务端认证时间不得早于 5 分钟前。删除最后一个
Passkey 时，即使 session 仍处于 5 分钟新鲜期，也必须在该操作中再次验证
备用密码。

备用密码长度 `MUST` 为 16～128 个字符，不强制字符类别组合；系统
`SHOULD` 建议使用密码管理器生成至少 24 个随机字符。密码不得通过命令行
参数、环境变量或日志传递。

Passkey 和备用密码同时失效时，只能通过服务器终端离线完全恢复。恢复
必须设置新密码、撤销全部 session 并删除全部旧 Passkey；系统不提供邮件、
短信或恢复码通道。

本地开发与远程部署使用不同认证策略。只有受控的 `pnpm dev` 或 `docker/local.sh` 启动入口
显式声明本地信任，并且运行模式为 `development`、public origin 与全部允许 Host 均为
loopback 时，应用才从已初始化数据库解析唯一管理员并自动进入管理界面，不显示登录或要求
凭据。容器内部为端口转发监听 `0.0.0.0` 不属于外部访问边界。`production` 和 `test` 永远
不启用该信任路径，即使 URL 是 localhost 或误设本地标记也继续执行正式认证。

正式部署成功登录后的 session 使用 90 天有效期，并在有活动时每 7 天滚动刷新；
密码登录显式记住本设备。Passkey 管理的 5 分钟近期认证规则不因此放宽，离线
完全恢复继续立即撤销全部现有 session。

### 2.3 图书生命周期与访问

图书是否已发布只由 `current_version_id` 表达；没有当前版本即为草稿，有当前版本即为
已发布。访问状态独立为 `private | public`，新导入图书 `MUST` 默认为 `private`，没有
已发布版本的图书不得设为 `public`。

匿名访问未发布或 `private` 图书的正文、图片、附件和下载地址时，系统 `MUST` 返回
`404`，而不是暴露资源存在。

### 2.4 文件夹可见性

匿名访客只看到至少包含一本已发布公开图书的文件夹分支。只包含未发布或私人图书的
文件夹 `MUST` 完全隐藏。

## 3. 信息架构与路由

### 3.1 路由

| 路由                       | 用途                             |
| -------------------------- | -------------------------------- |
| `/`                        | 展示型首页                       |
| `/library`                 | 完整书库根目录                   |
| `/library/[...folderPath]` | 书库中的任意层级文件夹           |
| `/books/:bookKey`          | 路由驱动的书籍详情弹窗           |
| `/read/:bookKey`           | 阅读入口，重定向到实际页面       |
| `/read/:bookKey/:pageKey`  | 实际阅读页面                     |
| `/search`                  | 全站搜索                         |
| `/login`                   | 管理员登录                       |
| `/manage`                  | 导入、任务、错误、存储和系统管理 |

旧的 `/folder/...` 路由已废弃，`MUST NOT` 实现。

### 3.2 图书和页面标识

每本书具有：

- 稳定数字 ID
- 可选全局别名 `alias`

每个页面具有：

- 书内稳定数字 ID
- 可选书内别名 `alias`

别名规则：

- 只允许小写字母、数字和连字符
- 不能是纯数字
- 图书别名全局唯一
- 页面别名在当前图书内唯一

当别名存在时，数字路由 `MUST` 重定向到别名规范地址。

别名修改后：

- 旧别名立即失效
- 不保留历史重定向
- 旧别名立即可复用
- 稳定数字 ID 仍可作为入口，并重定向到当前别名

### 3.3 文件夹路径

文件夹显示名与 URL slug `MUST` 分离。修改显示名不应自动修改 slug。

文件夹移动或 slug 修改后：

- URL 随层级变化
- 旧地址返回 `404`
- 旧路径立即可复用

## 4. 展示型首页

（这块精选书架这里可以先不实现）
首页只承担展示与氛围，不承担完整书库管理。

视觉方向：

- 与 `mirawind.top` 的 Astro Twilight 风格保持一致
- 复用色彩、背景、留白、卡片、圆角、阴影、字体和轻量动效的设计语言
- 不引入博客文章、归档、分类、评论或 RSS

首页 `MUST` 包含：

- 站点名称与简短说明
- 精选书架
- “查看全部书库”入口，指向 `/library`

首页书架支持：

- 手动精选书架
- 自动书架，例如最近加入、最近阅读
- 每个书架可单独隐藏、启用和排序
- 手动书架可配置名称、书籍和顺序

匿名访客只看到已发布公开书籍。管理员登录后可以看到包含私人或未发布书籍的个人自动书架。

私人书架数据 `MUST NOT` 出现在公开 HTML、公共缓存或搜索引擎内容中。

实体书架效果只用于装饰性展示，不得替代 `/library` 的完整管理界面。

## 5. 完整书库

### 5.1 页面模型

`/library` 和 `/library/[...folderPath]` 是同一套界面。根目录只是一个特殊文件夹。

M2a 先交付根目录书库与阅读闭环，完整嵌套文件夹和拖拽管理留在后续 M2
切片。根目录公共 HTML 只包含当前公开且具有完整已发布版本的图书，并且对匿名
访客与已登录管理员保持相同字节；管理员可见的未发布、私人图书和轻量状态通过
独立的非缓存已认证响应加载。

视图参考 KDE Dolphin：

- 文件夹和书籍在同一网格中混排
- 文件夹优先
- 支持图标网格和紧凑列表
- 不使用额外的“文件夹”“书籍”分区标题
- 每个文件夹记忆自身视图与排序设置

### 5.2 排序

每个文件夹支持：

- 标题
- 作者
- 导入时间
- 更新时间
- 手动排序

### 5.3 管理操作

管理员登录后，书库 `MUST` 支持：

- 新建文件夹
- 重命名
- 移动
- 删除
- 拖拽图书进入文件夹
- 拖拽文件夹调整层级
- 多选
- 批量移动
- 批量删除

系统 `OUT`：

- 通用文件复制
- 压缩
- 快捷方式
- 任意服务器文件操作
- 把逻辑文件夹映射为服务器物理路径

### 5.4 图书卡片

图书卡片只显示：

- 封面
- 标题
- 可选作者或整理者
- 管理员登录时的轻量状态标记

卡片 `MUST NOT` 显示：

- 阅读进度
- ISBN
- 文件格式
- 标签
- 描述
- 大量元数据

交互：

- 点击封面：直接进入阅读
- 点击书名或菜单：打开详情弹窗

## 6. 书籍详情弹窗

`/books/:bookKey` 是路由驱动的详情弹窗，不是独立页面模型。

行为：

- 从书库打开时，背景保留当前文件夹和滚动位置
- 关闭后恢复原位置
- 直接访问该路由时，先呈现书库背景，再打开弹窗
- 移动端使用全屏覆盖

直接请求详情地址时，服务端 `MUST` 返回完整书库背景与已打开的语义详情
dialog；关闭 JavaScript 后仍可查看详情、开始阅读和返回书库。来自书库的增强
导航可以使用浏览器 history 恢复原 URL、滚动位置和触发控件焦点，但不得建立
第二套路由状态权威。

内容包括：

- 封面
- 标题、作者等元数据
- 简介
- 目录预览
- 开始阅读
- 可用原文件下载
- 管理员管理操作

当保存多个原文件时，下载菜单显示格式与文件大小。

公开书库、详情、阅读器运行时标题和搜索结果展示 `MUST` 来自
`current_version_id` 对应不可变版本的有界派生投影。草稿配置中的标题、alias、
作者、简介或封面变化在新版本成功发布前 `MUST NOT` 出现在公共表示中。该投影
不是新的编辑权威，可以由 worker 从冻结的正文修订、出版设置和 manifest 重建；
阅读请求不得为此解析源配置。

M1 不设置独立的原文件下载开关。图书为 `public` 时，其登记为原文件的
MinerU ZIP、PDF、EPUB 等文件允许匿名下载；图书未发布或访问状态为 `private`
时仅管理员可以下载。正文 IR、切换前的 `book.yaml`、`document-manifest.json`、搜索索引、
私人笔记、批注和其他内部文件 `MUST NOT` 作为原文件下载。

下载响应 `MUST`：

- 使用 `Content-Disposition: attachment`
- 提供安全的 UTF-8 文件名和 ASCII 回退名
- 返回正确的类型、长度、`nosniff`、强 ETag 和 Range 支持
- 每次完整请求和 Range 请求都重新检查当前权限
- 返回 `Cache-Control: private, no-store`
- 通过 `X-Robots-Tag` 禁止索引、存档和摘要

## 7. 阅读器

### 7.1 页面结构

桌面端：

- 固定顶部阅读栏
- 左侧全书目录
- 中间正文
- 右侧当前页面提纲
- 私人笔记与批注使用按需打开的右侧抽屉

顶部栏 `SHOULD` 参考 D2L 的轻量风格，包含：

- 返回书库
- 书名或当前章节
- 搜索
- 书签
- 笔记
- 阅读设置

顶部栏 `MUST` 固定显示，不自动隐藏。

移动端默认只显示正文，目录、笔记和设置通过抽屉打开。

### 7.2 阅读导航

支持：

- 左侧目录
- 页面底部上一页、下一页
- 桌面键盘左右方向键

当焦点位于输入框、Vditor、代码交互区域时，方向键不得触发翻页。

移动端 `MUST NOT` 依赖左右滑动翻页。

正常翻页进入页面顶部；从搜索结果、书签、内部锚点进入时，跳转到目标位置。

### 7.3 阅读入口

`/read/:bookKey`：

- 管理员以前读过：跳转最后页面并恢复页内位置
- 管理员首次阅读：跳转第一内容页
- 匿名访客：跳转第一内容页

实际正文始终位于 `/read/:bookKey/:pageKey`。

详情弹窗应提供“从头开始”入口。

### 7.4 阅读设置

管理员可以设置：

- 字号
- 行高
- 正文宽度
- 浅色/深色
- 中文字体
- 拉丁字体
- 等宽字体

设置以全局为主，单书可覆盖，并跨设备同步。

匿名访客使用站点默认设置。是否提供匿名本地临时设置仍为 `OPEN`。

### 7.5 图片

- 保留 MinerU 原始图片质量
- 默认适配正文宽度
- 不超过原图尺寸放大
- 点击打开灯箱
- 支持缩放和平移
- 超宽图片允许横向滚动
- 移动端适配屏幕宽度
- 图名显示在图下方

### 7.6 表格

- 使用语义化 HTML 表格
- 表名显示在表格上方
- 保留原编号
- 超宽表格允许横向滚动

### 7.7 公式

- 使用 KaTeX
- 优先在发布时预渲染
- KaTeX HTML、CSS 与字体必须使用相同的版本化渲染器身份并由本地提供
- 每条有效公式视觉上只显示一次，同时保留 MathML 无障碍表示
- 保留原始 LaTeX
- 保留原书已有公式编号和正文引用
- 不给未编号公式自动编号
- 不统一重编号

KaTeX 渲染失败时：

- 导入预览显示诊断
- 不强制阻止发布
- 网页显示原始 LaTeX，并标记渲染失败

### 7.8 代码

- 使用语法高亮
- 支持复制
- 横向滚动
- 默认不显示行号
- 每本书可覆盖行号设置
- 保留源文件名或标题
- 未知语言按纯文本处理
- 不提供在线执行

### 7.9 脚注

- 正文使用上标编号
- 悬停或点击显示浮层
- 页面末尾保留完整脚注列表
- 正文与脚注双向链接
- 保留原编号

## 8. 输入与导入

### 8.1 MinerU

扫描 PDF、图片 PDF 和复杂 PDF 由外部 GPU 机器运行 MinerU。服务器 `MUST NOT` 在 MVP 中运行 MinerU 或 GPU 任务。

每次导入只接受一个完整 MinerU 输出 ZIP，且该 ZIP 只对应一本书。

系统只读取 `content_list_v2.json` 或 `<stem>_content_list_v2.json`，直接生成自有 IR。
没有独立格式适配器、旧 JSON/Markdown 导入、主 Markdown 确认或自动 fallback。
多个书籍 bundle、缺少必需 JSON、不支持的内容结构或缺失资源必须明确失败。
资源路径相对该 v2 JSON 所在目录解释，通过统一存储原语定位。
新 ZIP 创建新图书，已有工作稿通过块编辑和出版设置保存修改，不保留原包重处理接口。

导入流程：

1. 上传
2. 解包
3. 解析和校验
4. 显示诊断
5. 自动重建印刷目录、正文匹配、层级与初始拆页，并接纳清理后的活动正文 IR
6. 生成草稿预览
7. 发布

可用 v2 正文候选不唯一时导入失败，不提供主文件确认或旧格式回退。
印刷目录区域、canonical、正文匹配、层级和初始拆页不得等待人工答案，
也不得读取显式出版覆盖作为分析证据。

接纳后原 ZIP 保存在书籍 `originals/`，导入记录指向这唯一副本，上传暂存与解包副本清理。
失败的未完成写入与 staging 立即清理，原始包不按固定时长删除。

发布和公开是两个独立操作。发布只晋升管理员已预览的不可变候选并保留当前
`private | public` 访问状态；没有已发布版本的图书不得设为 `public`。

校验至少包括：

- MinerU v2 内容结构与生成的 IR
- 引用图片
- 数学公式
- 元数据
- 目录候选
- 印刷目录参考区域、正文标题匹配和结构冲突
- 缺失资源

导入按 D-140 假定管理员善意，不执行独立 ZIP 或图片安全检查，也不保留其专用安全测试。
ZIP 由 zip.js 单次流式解包，图片由 Sharp 读取格式与尺寸。保留正常格式解析、资源定位、
任务取消和失败清理。MinerU v2 JSON 与 IR 执行以下解析预算。
正文另限 20,000 个顶层块、100,000 个有身份节点、1,000,000 个 JSON 节点、
128 层 JSON 深度和 32 层块深度；字符串限制由正文 schema 与语义校验共同执行：

| 限制                |    数值 |
| ------------------- | ------: |
| 上传 ZIP            |   2 GiB |
| MinerU v2 JSON / IR | 256 MiB |
| 后台导入或重建      | 30 分钟 |

不设置解压倍率、归档条目数、解压体积或图片像素安全门禁。上传和正文解析预算仍按实际
读取的数据执行；解析失败或任务取消时清理未完成的暂存目录。
任务失败只使用 infrastructure、content、validation、timeout、canceled；普通内容预算
超限属于 content。D-142 清理数据库及 IPC／健康状态中的旧审查分类，错误类别在 Publishing
集中定义。现有操作日志记录登录管理和出版变更，不记录导入安全审查结果。

### 8.2 EPUB

EPUB 直接上传，由系统解析，不经过 MinerU。

EPUB 支持不进入首个垂直切片。最终实现 `MUST` 将 EPUB 转为同一正文 IR，再生成普通语义
HTML，不使用 iframe 作为最终正文载体。

具体解析库仍为 `OPEN`。

### 8.3 原始文件

M1 将上传的 MinerU ZIP 登记为该版本的可下载原文件。后续支持的原 PDF、
图片包和 EPUB 可以使用相同模型登记。

原文件：

- 不作为主正文
- 不参与服务器端 MinerU 处理
- 可单独删除，而不影响网页版图书
- 下载权限直接跟随图书访问状态和发布生命周期，不使用独立下载开关

### 8.4 MinerU 包清理

MinerU ZIP 是导入包，不是网页运行格式。上传的原 ZIP 作为登记原文件保留
以供下载；网页正文不在请求时从 ZIP 解压或解析。

系统永久保存：

- 已接纳的正文 IR
- 正文实际引用的图片
- 与正文同一修订的出版设置和必要元数据
- 上传的原始 MinerU ZIP
- 其他已登记原始文件

完成接纳并保存所需私有来源证据后，系统应清理不再需要的解包副本；原始 ZIP 不变：

- `layout.pdf`
- `span.pdf`
- `middle.json`
- `model.json`
- 未引用临时资源
- 调试中间产物

## 9. 更新、重新导入与事务

当前更新通过工作稿保存完成，不接受以 ZIP 指定已有目标图书。
新 ZIP 始终创建新书，不按标题、ISBN、文件名或包内标识合并，也不继承旧书历史与地址。
保存提交 `expected_updated_at`；冲突保留本地编辑，不允许静默覆盖。
面向已有图书的新包重导入与批注重定位留待后续独立实现。

每本书使用同一文件系统内的 staging 目录与按 `version_id` 命名的不可变
`builds/<version_id>/` 产物目录。SQLite 的 `current_version_id` 是当前发布版本的唯一权威指针；
文件系统 `MUST NOT` 维护第二个 `current` 指针或可变当前目录。

保存直接在 SQLite 原子提交变化的根块、元数据、出版设置和 `updated_at`，返回 `200`。
所有 block（含标题、列表项和嵌套块）统一通过 `PATCH /draft` 的 `blocks[]` 提交，以
`block_id` 定位；`markdown` 是局部输入语法，标题可附带 `level` 等类型字段。删除独立
标题保存格式与单块 PATCH。字段／引用校验在 Publishing 共用，只有层级、拆页或 alias
等结构变化读取有序标题上下文；元数据、编号模式不读取正文。不保留整书编辑回退路径。
同批允许独立块与同根兄弟节点，互相包含的父子编辑拒绝，所有变更一起成功或回滚。
相同请求身份重试返回已接纳结果，不再应用修改。浏览器串行自动保存，输入静止 600 ms 后提交；
提交后继续输入保留在本地并合并到下一次保存，冲突保留本地内容。设置弹窗仍显式保存。

构建与发布使用文件先固化、数据库后切换的两阶段协议：

1. 保存事务中合并同书 `build_book` 需求，延迟 1 秒启动；手动刷新预览可立即启动排队任务。
   同书旧输入正在构建时请求取消，沿用 10 秒终止宽限，不抢占其他书。worker 读取一致数据库
   快照，再于事务外写出固定 `book.json`、编译和校验完整产物。
2. 持久化全部文件后，原子重命名为不可变版本目录。
3. 在一个 SQLite 事务中写入 `ready` 产物、带版本 ID 的 FTS5 索引、展示投影和成功任务终态；
   不维护独立 candidate 表或第二套身份。
4. 发布请求在与保存共用的按书串行边界内校验候选 `source_updated_at` 与当前工作稿时间
   一致，并核对候选构建身份、阻断诊断和前任版本，不重新编译正文。
5. 保持该串行边界，通过短事务原子更新 `current_version_id`、新旧版本状态和审计记录。

版本进入 `ready` 时，书库展示投影 `MUST` 与版本记录和 FTS 行在同一事务中
登记并校验。最终切换事务还必须确认投影身份与摘要匹配，并把该版本冻结的
alias 与 `current_version_id` 一起提升；alias 唯一性冲突必须使切换整体回滚。

任何构建、FTS5、版本比较或数据库提交失败都必须继续服务完整旧版本。
`ready` 或孤立版本不得自动公开。启动恢复必须识别 staging、孤立目录、
缺失文件和损坏当前版本；当前版本损坏时回退到最近一个校验通过的已发布
版本，无可回退版本时只让该书返回 `503`。

发布事务不得删除旧版本。M1 至少保留当前版本和上一个成功发布版本；更早
版本从被替换时起等待至少 24 小时后连同其 FTS5 数据清理。被替换的未发布预览
从被替换时起保留 1 小时，当前预览不回收；损坏且不再是当前版本的产物保留 24 小时。
worker 每 60 秒在任务之间分批回收，不等待队列清空；完整目录核对仍在空闲进行。
已回收版本保留数据库中的不可变谱系与 `reclaimed_at` 时间墓碑，但不得再被
读取、搜索或用于恢复；文件删除失败由后续回收重试，不影响当前发布结果。
成功删除记录 `files_removed_at`，后续不再扫描这些历史文件路径。

资源库与正文依赖必须分开。导入图片、原 ZIP 默认随书保留；上传封面按真实引用保留。
块修改事务只更新所属根块的资源 ID 索引，构建快照及清单只捕获正文、封面实际使用的图片。
ZIP 的保留及授权下载独立于正文构建，不重复读取 ZIP 来构建正文。资源选择器读取资源库，
不依赖预览是否就绪。上传图片没有草稿、保留产物或同书运行任务引用满一小时后，事务复核
并标记待删除，文件删除成功后移除登记；待删除资源不能重新接纳到正文。回收失败可重试，
不改变正文 `updated_at`。这些引用索引不保存正文副本或手工引用计数。

## 10. 结构化正文与发布模型

### 10.1 唯一可编辑正文

接纳后的 Mirawind 自有结构化正文 IR `MUST` 成为唯一可编辑正文权威。正文、标题和可移植
出版设置形成同一个一致修订。MinerU v2 JSON 直接转入 IR；局部 Markdown 仅是现有块编辑框
语法，不支持整篇导入/导出，也不保存为第二份正文。

具体字段见[结构化正文 IR 设计](../architecture/structured-content-ir.md)。工作稿存在 SQLite 的
`book_documents`、有序 `book_blocks` 中，嵌套节点通过 `book_nodes` 定位所属根块。
格式冻结为 IR v1、manifest v5 与完整性标记 v5。D-141 授权删除本项目旧运行目录后重新导入，
没有旧库转换器或兼容读取；其他应用、真实样本和独立参考证据不在删除范围。

工作稿可以修改，不要求每次保存都保留不可变整书历史。`book_documents.updated_at` 只使用
服务端 Unix 毫秒整数 `updated_at` 作为最后修订时间与保存冲突标识，不另设 `revision`，
也不维护第二份权威草稿时间；`schema_version` 只表示格式版本。首次接纳由
服务端当前时间初始化，后续有变化的保存使用 `max(now_ms, previous_updated_at + 1)`。
同毫秒保存和时钟回拨时仍严格递增，因此该值不保证精确等于实际修改时刻。

保存必须携带原始精度的 `expected_updated_at`，服务端在所有写入者共用的按书串行边界内
比较并将新时间与变化根块一起原子写入。解析和语义校验在写事务外完成。
禁止用客户端时钟或文件 `mtime` 代替它；过期或非法值拒绝，未保存编辑和无变化保存不推进时间。
权限、笔记、预览和发布操作不修改正文时间。

构建从一致的工作稿快照读取，记录 `source_updated_at`；`book.json` 只在不可变构建中保存。
图片和原始 ZIP 每书共享一份，完整性标记分别登记产物文件和共享文件，不随保存或构建复制。
工作稿可继续编辑。保存与构建调度在同一 SQLite 事务提交，不需要跨文件保存恢复协议。

### 10.2 统一内容模型

导入时：

- 使用成熟的 ZIP/JSON/HTML 解析组件，直接处理唯一的 MinerU v2 输入
- 生成并严格校验自有 IR
- 为可批注内容生成稳定块 ID
- 目录、拆页、搜索、高亮和最终 HTML 都基于同一 IR 修订及其编译结果

第三方解析器 AST 只在导入或编译期间存在；自有 IR 作为正文持久化。HTML、manifest、导航、
资源服务映射与搜索索引仍为可重建产物。IR 的块保存内容和身份，不要求 Markdown 字符串
偏移、文本指纹或预处理摘要链；源坐标属于私有导入证据，完整性摘要属于存储与发布协议。

稳定 ID 分配给标题、段落、列表项、引用、代码块、公式、图片、表格、脚注
和教材语义容器，不分配给行内格式。新书导入时随机生成，不继承旧库身份；旧 ID 不复用。

修改已有块保留其身份，复制或插入分配新身份。阅读顺序由有序内容表达，不从 ID 推断；
不因标题、文字或位置改变重新编号。manifest 保存阅读所需的派生锚点与映射，不再要求以
Markdown 源位置定位正文。新 IR、manifest 与 version marker 必须独立版本化，并在运行时
具备 fixtures 与干净切换证据；本次不实现旧库迁移或兼容格式读取，未知字段与不支持版本严格拒绝。

M1 的可见文本规范化使用渲染后文本、Unicode NFC 和统一换行；精确高亮
偏移规则推迟到 M3。

导入准备先从完整输入建立私有分析证据，再排除印刷目录和 MinerU 重复辅助块，接纳活动
正文 IR。只有活动正文进入结构、分页、搜索和发布；原始 ZIP 保持不可变。区域、canonical
和正文匹配证据独立保存，不混入正文。目录派生自标题及其层级，不保存另一棵可独立编辑、
与正文重复维护的目录权威树。图书访问状态、发布指针和私人笔记不属于正文模型。

### 10.3 语义 HTML

正文 `MUST` 是完整语义 DOM：

- `h1`–`h4`
- 段落
- 列表
- 引用
- 表格
- 脚注
- 代码
- 公式
- 图片与题注
- 特殊教材块

正文 `MUST NOT` 使用以下形式作为主内容：

- PDF.js
- Canvas
- 页面截图
- iframe
- 仅客户端 JavaScript 生成正文
- 视口虚拟化导致当前页面正文不在 DOM 中

### 10.4 发布

公开正文由单书编译器增量生成：

- HTML
- 页面 manifest
- 全书目录
- 页面提纲
- KaTeX 结果
- 代码高亮结果
- 搜索索引数据
- 资源映射
- 构建诊断

草稿预览和正式发布必须来自同一次候选构建。后台只建立一个整书
`CompiledBook`，其中保存一次解析的文档树、配置后的标题、仅含区间与 ID 的页面计划、
身份、诊断和逻辑资源；页面以有背压、最多四页并发且按序交付的方式逐页渲染、写入并释放。
相同的 IR 修订、源资源与冻结构建身份产生相同的活动文档、标题层级、编号、
拆页、正文和诊断；预览与公开表示只允许在授权资源 URL、外壳、缓存、索引和能力策略上
不同。构建记录以 `source_updated_at` 绑定输入快照并验证完整性，正文或出版设置变化后旧预览
失效。保存和发布共用的按书串行边界必须覆盖来源时间检查至发布指针提交。发布只原子晋升
管理员已经预览的 ready candidate，不得再次解析、编译、渲染或建立搜索。

系统 `MUST NOT` 每导入一本书就执行整站 Astro rebuild。

所有生成产物保存在非公开数据目录。Astro 根据状态与权限读取并返回。

上传、重新导入和出版配置变化只触发后台单书重建。阅读请求只读取已发布的
预生成版本，`MUST NOT` 在请求路径中解析整书 IR 或 Markdown、构建 AST、运行 KaTeX、
执行代码高亮或生成搜索索引。重建期间继续服务旧版本，成功后原子切换。

公开书籍：

- 允许公共缓存
- 允许搜索引擎索引

私人或未发布书籍：

- 必须鉴权
- 禁止公共缓存
- 禁止搜索引擎索引

## 11. 目录、拆页与链接

### 11.1 目录生成

来源优先级：

1. EPUB nav 或可靠书签
2. 导入表示中的标题语义及版面证据
3. 标题样式和正则候选
4. 未来可选 LLM 辅助

出版工作台允许管理员显式覆盖最终展示配置：

- 选择目录标题
- 重命名
- 调整层级
- 确认拆页
- 设置正文起点，以及可选的附录和后置内容起点

M1 不允许在目录界面拖拽改变正文顺序；IR 不以必须修改 Markdown 为重排前提，但重排
编辑功能不随本次架构决策自动交付。页面 alias 继续保留，M1 不提供编辑入口。

目录勾选只决定标题是否出现在全书导航中，不得删除或隐藏对应正文。标题展示保留
统一的行内内容，标题、层级和拆页设置在同一 IR 修订中接纳；正文、附录和后置角色由三个线性
边界按源顺序派生，不逐标题保存角色。

配置后的层级决定目录、页面提纲、编号和最终 `h1`–`h4`，并且必须连续有效。
M1 只允许在标题节点前拆页，不允许在段落、公式、表格或图片中间拆页。

管理界面负责提交类型化编辑；系统校验并原子接纳新的正文与出版设置修订，管理员无需
手工编辑持久化文件。过期修订的保存必须拒绝，不能静默覆盖。

这些显式修改只改变已接纳内容与最终出版设置，不参与印刷目录区域、canonical、正文匹配、
层级或初始拆页的自动分析，也不能用于通过内容正确性门禁。

印刷目录是独立于普通目录勾选的准备证据。后台自动识别具有明确目录边界、
章节编号、页码和后续正文匹配的候选，将其作为结构参照并从活动正文排除；
原始 ZIP 保持不可变。准备分析保存排除范围、canonical 选择及条目到正文标题的
一对一匹配。当前阶段不设置区域、canonical、正文匹配或层级的人工
裁决步骤；重复标题、顺序冲突、缺失匹配和低置信结果必须生成可定位诊断，不得
等待人工确认后静默接受。纸质页码不得直接转换为网页分页。

识别不能依赖单个“目录”标签或 MinerU JSON 的初始标题级别。导入 worker 必须联合
前置位置、目录/Contents 标签、连续或空格点线、普通右侧页码、重复标题序列、页内栏序与
缩进，以及后续正文按顺序复现的证据。一本书可以有多个印刷目录区域（例如简目和完整目录）；
识别后这些区域都从阅读、搜索和导航排除，但只能有一个规范区域提供初始层级。位于正文后的
索引必须通过位置和正文复现方向排除。

目录条目与正文标题使用允许局部跳过的全局顺序匹配。边界可信度与单个条目匹配可信度必须
分开评估；某个条目缺失或歧义不能使其他可靠匹配失效。Part/篇/部分是顶层单元，其内部章
下降一级；没有 Part 的章保持顶层，附录和明确的后置单元重置顶层上下文，最终层级限制为
连续的 `h1`–`h4`。可靠编号的正文独有标题和明确的无编号前后置单元可以进入目录，但必须
携带来源和可信度诊断。

上述自动分析必须在无人工答案输入的情况下完成。Codex 对 PDF 页面图像建立的
reference v3 使用独立 PDF 目录转写和原始 v2 JSON 的直接内容核对，只用于本地离线验收；
旧 Markdown 观察记录不再读取。参考真值不进入导入、预览或发布运行链路。既有显式
出版覆盖不得作为自动识别证据，也不得用于修补十五本正确性门禁的生产输出。

### 11.2 标题编号

每本书可以选择保留原书编号、仅为正文自动生成编号，或隐藏全部编号；默认保留原书编号。
编号与无前导序号的标题内容分别编译，在正文、目录、提纲、面包屑、页面元数据和搜索中只
组合一次。切换模式只修改出版设置，不改写标题内容或删除已识别的原书编号。

自动编号只作用于派生角色为正文的标题，并按最终连续标题层级生成。前言、序言、导论、
符号表等前置内容，附录，以及后记、参考文献、索引、致谢等后置内容均不自动编号。进入正文
时从 `1` 开始；正文首个标题不是一级时也不得产生 `0.1` 等零前缀。

保留原书编号模式可以继续展示正文、附录或其他内容中已识别的来源编号；隐藏编号模式在所有
标题表示中隐藏编号。管理界面使用同一个整书级选择，不为正文和目录提供相互独立的开关。

### 11.3 拆页

默认：

- Part、非相邻的章、附录和独立主要前后置单元开始一页
- Part 后紧邻的第一章不额外产生空白或标题页；后续章即使是二级标题仍开始新页
- 普通节和小节默认不拆页
- 层级调整不得隐式改变管理员已经确认的拆页选择
- 每本书可人工覆盖

### 11.4 内部链接

系统必须保留和修复：

- 标题链接
- 图表引用
- 公式引用
- 脚注
- 跨页面链接

系统不得把普通文本引用凭猜测自动转成链接。

### 11.5 出版工作台即时试排

出版工作台是校对与例外处理界面，不是编译器遥测面板。管理员切换整书编号方式、修改标题、
调整标题层级、切换目录可见性或折叠目录分支时，结构区 `MUST` 在浏览器内立即显示最终目录
形态。即时试排不得发送保存请求、更新 `updated_at`、入队或运行 worker，并且必须明确标记尚未
保存的状态。

即时试排只负责目录表示和本地编辑反馈。管理员保存后，系统才原子更新工作稿及 `updated_at`，
由 worker 捕获固定输入并生成正式正文、分页、manifest、搜索和展示投影；未保存试排不得发布或进入公共
表示。目录当前可见行必须即时渲染标题中的行内公式，选中的独立公式块必须在字符编辑时显示
KaTeX 试排；两者都不代替保存后的正式 worker 输出。结构列表在 20,000 个标题上仍必须虚拟化、
有界且保持可交互，不得为了公式试排渲染不可见标题。

主工作台 `MUST NOT` 默认显示 typography profile、空格/标点调整计数、保护节点数或空诊断
板块。只有阻断发布或确实建议检查的诊断进入问题入口；机器 code、阶段、置信度、字节范围和
区域身份只在技术详情中显示。自动排版记录不称为问题，恢复原文不作为每条记录的重复操作。

工作台左侧结构树是草稿预览唯一的目录导航。点击任意标题必须立即让中间画布载入其 `page_id`
并定位 `block_id`；草稿 iframe 只显示正文、翻页与可编辑块，不重复显示 Reader 顶栏、面包屑、
目录、页内提纲、移动目录按钮或抽屉。公开 Reader 不受影响。右侧检查器只保留标题输入和一份
即时富文本试排，不得重复展示同一编号/标题。桌面三栏顶部对齐，目录行保持 36 px 稳定高度、
无逐行分隔线并继续虚拟化。

## 14. 搜索

第一版使用 SQLite FTS5，不部署独立搜索服务。

索引范围：

- 书名
- 作者
- 章节标题
- 正文块
- 私人笔记和批注的独立索引范围

匿名访客只搜索公开正文。

管理员默认搜索所有可见正文，并可切换到“笔记与批注”。

搜索结果标记来源：

- 正文
- 笔记
- 批注

结果应定位到：

- `book_id`
- `page_id`
- `block_id`

正文主索引使用 FTS5 trigram 和 `detail=full`。3 个及以上 Unicode 字符
搜索书名、作者、章节标题和正文；1～2 个字符只对书名、作者和章节标题执行
受限 `LIKE` 或 `instr()` 回退，不扫描完整正文。界面必须明确提示短查询
范围。

查询使用与索引一致的 NFC 和换行规范化，并编码为安全的 FTS5 字面短语。
M1 不使用 `unicode61` 作为中文正文主索引，不引入中文分词扩展或全正文
短词表。所有查询继续同时过滤权限和 `current_version_id`。

## 18. 存储、部署与删除

### 18.1 部署

- 单台 Linux 服务器
- Docker Compose
- Astro Node Web 进程
- 同代码库独立 worker 进程
- React Islands
- SQLite + WAL
- SQLite 持久化任务队列
- 本地文件系统
- Caddy 或等价反向代理
- HTTPS
- 单 Web 实例和单 worker 实例

本地预览按 D-098 提供 `./docker/local.sh` 统一入口：它用一个 Compose 项目管理
仍然相互独立的 Web 与 worker，只把 Web 发布到 `127.0.0.1:4321`，自动生成
Git 忽略且权限为 `0600` 的随机本地配置，并通过交互式离线 CLI 完成首次管理员
初始化。该 localhost HTTP 覆盖层不启用 Caddy、不能对外暴露，也不改变上述
生产 HTTPS 拓扑。

M1 全局同时只运行一个导入或重建任务。worker 使用租约心跳领取任务，每个
任务在可终止子进程中执行；进程或服务器中断造成的任务最多自动重试一次，
资源超限、内容错误或第二次中断不得自动重试。已构建为 `ready` 的版本不得
因恢复流程自动公开。任务取消或达到 30 分钟上限时先请求协作式终止；10 秒
内未退出则强制终止整个任务进程组，确认关闭后才能写入最终任务状态。

认证管理健康接口还必须从 worker 的私有健康快照显示 queued/running 数量、最老排队
时长、当前或最近 attempt 的总耗时、逐阶段耗时和任务子进程树峰值 RSS。worker 以有界
频率更新该快照；采样不可用必须与零值区分且不得使任务失败。观测数据只允许包含不透明
任务 ID、安全状态和有界聚合值，不得包含正文、原始文件名、原始归档路径或凭据。

本地 Node.js 开发使用一个 `pnpm dev` 同时拥有 Web 和 worker，不能出现 Web 可上传但
没有任务消费者的半启动状态。持久队列只承载用户发起的导入、草稿、预览和删除；worker
启动后先领取这些任务，只在队列为空时运行一次内部存储核对、当前版本检查和过期文件清理。
内部维护不创建任务记录，也不进入管理任务列表。候选构建在界面称为“生成阅读预览”，
不暴露内部流水线名称。

源码开发入口通过 Astro `dev()` API 持有 Web 生命周期，先等待 worker ready 再开放 HTTP；
启动器与 worker 退出时相互关闭，禁止留下只有 Web 的可上传状态。文件热更新不监听持久数据、
缓存和大型导入样本。本地免登录 session 访问安全页时显示开发身份状态，不调用正式 Passkey API。

不使用：

- 微服务
- PostgreSQL/MySQL
- Redis
- 对象存储
- 分布式任务系统
- 多服务器共享 SQLite

### 18.2 存储统计

管理页显示：

- 磁盘总量、已用、剩余
- 每本书占用
- 网页正文与图片
- 原始附件
- 笔记与历史

原始附件可独立删除，网页版继续保留。

### 18.3 永久删除

删除图书后：

- 立即从书库、搜索和公开访问中隐藏
- 同时从管理员书库、详情、阅读、资源和下载中隐藏
- 自动取消该书尚未完成的导入、草稿准备和候选构建任务
- 由后台任务永久清理全部数据库内容和文件系统数据
- 清理失败或中断时保持隐藏并安全重试
- 不提供恢复、保留窗口或回收站
- 只保留不含书名、正文、文件名和存储路径的最小审计墓碑

当前只支持单本删除。管理员必须输入当前显示书名确认；操作使用现有有效
管理员 session 和同源写入保护，不额外要求最近 5 分钟重新认证。批量删除
留在后续书库管理切片。

### 18.4 数据持久性

备份不作为产品 UI 功能。

但应用升级和卸载 `MUST NOT` 默认删除宿主持久化数据。迁移到新机器时，应支持复制持久化数据目录并运行一致性检查。

## 19. `/manage`

全站界面遵循静默原则：仅显示操作名称、字段标签、必要状态与可处理错误。禁止重复解释同一
操作、展示后台实现细节或添加教程式引导；技术信息按需展开。删除确认只保留目标书名、确认
输入和操作按钮，字段校验与不可恢复语义不变。

`/manage` 只处理：

- 导入
- 后台任务
- 错误与重试
- 存储统计
- 永久删除清理任务状态与失败重试（删除入口仍位于 `/library`）
- 系统设置

普通图书和文件夹管理直接在 `/library` 中完成，不在 `/manage` 重复实现。

## 20. SEO 与缓存

公开内容默认可被搜索引擎索引：

- `/`
- 公开 `/library/...`
- 公开 `/books/:bookKey`
- 公开 `/read/:bookKey/:pageKey`

不索引：

- `/search`
- `/login`
- `/manage`
- 私人或未发布图书
- 私人笔记、批注、书签、进度
- PDF、EPUB、MinerU ZIP 等原文件下载响应

规范地址优先使用当前 alias。

缓存规则：

- 公开 HTML：`public, max-age=0, must-revalidate`，使用包含当前版本、
  请求路由和渲染器版本的强 ETag
- 公开书籍的版本化图片等阅读资源：
  `private, max-age=31536000, immutable`
- PDF、EPUB、MinerU ZIP 原文件下载：`private, no-store`
- 未发布图书、`private` 图书、登录、管理页面和私人 API：`private, no-store`
- alias 跳转、不存在路径和隐藏私人资源的 `404`：`no-store`
- 带内容哈希且不含书籍数据的站点 JS、CSS 和字体：公共长期 immutable

公开可缓存 HTML `MUST NOT` 包含管理员身份或私人状态。书籍改为私人后，
服务器必须立即拒绝新的匿名访问；已经在公开期间交付给客户端的副本无法
收回。

`/library` 和公开 `/books/:bookKey` 属于上述公共 HTML，不能因请求携带管理员
Cookie 而改变字节或加入 `Vary: Cookie`。管理员书库增强使用
`private, no-store` 的独立管理 API。公开详情与搜索增强 JSON 可以重新验证，
但必须返回禁止索引的 `X-Robots-Tag`。能确认是当前公开书但当前投影、manifest
或必要文件损坏且无法恢复时，只让该书返回不缓存且不包含内部原因的 `503`。

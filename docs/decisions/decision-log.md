# Mirawind Library 决策日志

## D-140：导入假定管理员善意，删除独立安全审查

- 状态：Accepted；2026-09-08 所有者明确要求。
- 原则：信任管理员上传的 MinerU 输出，不针对恶意导入包设计独立安全检查或专用安全测试。
- 实现：删除 ZIP 预扫描、重复身份核对、归档路径审查注册表、特殊文件属性审查、解压倍率、
  解压体积、条目数及路径预算。使用 zip.js 单次流式解包；文件仍通过统一存储定位原语写入。
  图片仅由 Sharp 读取格式和尺寸，不执行扩展名/魔数交叉检查、像素预算或额外完整像素扫描。
- 界面：导入阶段改称“解包”，不再显示“安全检查”。
- 正确性：保留 MinerU/IR 格式校验、资源存在性和存储目录约束、上传及 JSON 解析预算、任务取消/
  超时、失败清理、发布完整性与恢复。登录、授权、私人资源响应、缓存和索引契约不变。
- 测试：删除专用恶意 ZIP/图片安全测试及其夹具生成器；保留导入功能、取消、失败清理和内容证据。
- 影响：不再承诺抵御恶意归档或图片；善意但损坏的输入可能在普通解析过程中失败。
  无正文 schema 变更、迁移或数据清理，既有书籍和导入记录继续使用。
- 替代：宪章升级到 5.0.0。旧决策、已完成 feature 记录和历史验收中关于导入安全审查及其
  专用测试的要求由本决策替代；其他正确性、认证授权和持久性要求继续有效。

- 文档状态：`M1 Accepted Baseline v1.0`
- 日期：`2026-07-25`
- 用途：记录已冻结决策及被替代方案
- 注意：本文件记录“为什么”；当前产品行为以 `docs/product/product-spec.md` 为准

## D-001：产品以语义化网页图书为核心

- 状态：Accepted
- 决策：主正文由 Markdown/EPUB 转换为普通语义 HTML。
- 原因：需要统一排版、全文搜索、SEO、稳定链接和浏览器 AI 可读性。
- 排除：PDF.js、Canvas、页面截图、iframe 作为主正文。

## D-002：采用单用户管理员模型

- 状态：Accepted
- 决策：匿名访客可读公开内容；唯一管理员可编辑和访问私人内容。
- 原因：降低权限、并发和产品复杂度。

## D-003：采用 Passkey + 备用密码

- 状态：Accepted
- 决策：Passkey 为主要登录方式，备用密码用于恢复。
- 原因：兼顾安全性和单用户可恢复性。
- 约束：不自行实现 WebAuthn 协议。

## D-004：图书状态为 draft/private/public

- 状态：Accepted
- 决策：新导入默认 draft；匿名访问非公开资源返回 404。
- 原因：防止导入后意外公开，避免泄露资源存在。

## D-005：首页与完整书库分离

- 状态：Accepted
- 决策：`/` 是展示首页；`/library` 是完整书库。
- 原因：首页用于品牌和精选展示，书库用于浏览、管理和搜索。
- Supersedes：早期“`/` 即完整书库”的方案。

## D-006：Library 与 Folder 合并为一套路由

- 状态：Accepted
- 决策：根目录和所有文件夹统一使用 `/library/[...folderPath]`。
- 原因：避免两套页面逻辑，面包屑和状态管理更自然。
- Supersedes：`/folder/...`。

## D-007：文件夹显示名和 slug 分离

- 状态：Accepted
- 决策：显示名可改而不自动改变 URL；slug 独立配置。
- 原因：保证可读路径与显示语言可独立调整。

## D-008：旧别名和旧文件夹路径不保留重定向

- 状态：Accepted
- 决策：修改后旧地址立即 404 并可复用。
- 原因：单用户系统不需要维护复杂路由历史。
- 风险：外部旧链接失效；这是明确接受的行为。

## D-009：采用路由驱动的书籍详情弹窗

- 状态：Accepted
- 决策：`/books/:bookKey` 打开书库背景上的详情弹窗。
- 原因：保留书库上下文，同时支持可分享和直接访问。

## D-010：阅读器布局参考 D2L

- 状态：Accepted
- 决策：固定顶部栏、左目录、中正文、右页面提纲。
- 原因：适合教材阅读和章节导航。
- 修订：顶部栏固定显示，不自动隐藏。

## D-011：不在书库卡片显示阅读进度

- 状态：Accepted
- 决策：卡片仅显示封面、标题、可选作者和管理员状态标记。
- 原因：书库选择界面保持简洁，避免与阅读器职责混杂。

## D-012：MinerU 在外部 GPU 机器运行

- 状态：Accepted
- 决策：服务器只接收 MinerU 输出 ZIP，不运行 MinerU。
- 原因：部署服务器无需 GPU，减少依赖和任务复杂度。

## D-013：EPUB 直接解析，不经过 MinerU

- 状态：Accepted
- 决策：EPUB 由系统解析为内部文档模型。
- 原因：EPUB 本身已有结构、目录和语义信息。
- 约束：最终正文不是 iframe EPUB 阅读器。

## D-014：MinerU ZIP 是导入包，不是永久运行格式

- 状态：Accepted
- 决策：保留 Markdown、引用资源、配置和可选原文件；清理中间产物。
- 原因：减少存储浪费和调试文件污染。

## D-015：Markdown 是唯一可编辑正文源

- 状态：Superseded by D-136；以下为切换前的历史决策
- 决策：结构树和 HTML 均为派生产物，不存在第二份人工编辑正文。
- 原因：避免双向同步和数据分叉。

## D-016：使用标准化文档树和稳定块 ID

- 状态：Accepted
- 决策：导入时解析 Markdown，生成标准化文档树；目录、搜索、高亮和 HTML 基于该树。
- 原因：为跨页链接、稳定定位和批注迁移提供统一基础。
- 限制：具体 schema 仍待冻结。

## D-017：高亮使用稳定块 ID + 文本锚点

- 状态：Accepted
- 决策：保存块 ID、偏移、exact、prefix、suffix 等复合锚点。
- 原因：兼顾快速精确定位和正文修改后的恢复。
- 约束：普通高亮不能跨正文块；公式、表格、图片整体批注。

## D-018：无法可靠迁移的批注进入待重新定位

- 状态：Accepted
- 决策：不静默删除，不做宽松 LLM 猜测。
- 原因：教材中重复文本多，错误挂载比暂时失联更危险。

## D-019：公开正文采用单书增量预生成

- 状态：Accepted
- 决策：每次只编译当前书，不执行整站 Astro rebuild。
- 原因：藏书增长后整站构建成本不可控，单书失败也不应影响全站。

## D-020：所有发布产物存放在非公开目录

- 状态：Accepted
- 决策：Astro 统一鉴权和返回公开/私人 HTML 与资源。
- 原因：避免私人 HTML、图片和附件绕过权限。
- 排除：将私人资源放入 Astro `public/`。

## D-021：采用 Astro 单体架构

- 状态：Accepted
- 决策：Astro 同时负责页面、API、鉴权和管理界面；复杂交互使用 React Islands。
- 原因：单用户、单服务器项目无需独立后端和微服务。

## D-022：采用 SQLite + WAL

- 状态：Accepted
- 决策：SQLite 为主数据库，应用保持单实例。
- 原因：写并发低、部署简单、数据主要位于本地文件系统。
- 升级条件：多用户、多实例或持续高并发写入时再评估 PostgreSQL。

## D-023：采用 SQLite FTS5

- 状态：Accepted
- 决策：正文和私人数据搜索使用 FTS5，不部署独立搜索服务。
- 原因：规模和单机部署模型适配。
- 未决：中文一至二字查询的最佳回退策略。

## D-024：本地文件系统保存图书资源

- 状态：Accepted
- 决策：Markdown、图片、原文件、发布产物和临时工作目录均在宿主持久化目录。
- 原因：无需对象存储和分布式文件系统。

## D-025：更新图书使用原子替换

- 状态：Accepted
- 决策：新版本在临时目录完整构建，成功后切换。
- 原因：用户不能看到半成品；失败不影响旧版本。

## D-026：服务器配置在重新导入冲突时优先

- 状态：Accepted
- 决策：文件夹、元数据、别名、目录和人工拆页配置默认保留。
- 原因：重新导入主要更新正文，不应破坏服务器已维护状态。

## D-027：不根据标题、ISBN 或文件名自动合并

- 状态：Accepted
- 决策：更新必须显式选择目标书或携带稳定 book_id。
- 原因：避免误合并不同版本和同名图书。

## D-028：公式使用 KaTeX

- 状态：Accepted
- 决策：发布时预渲染；保留原 LaTeX 和原编号。
- 原因：与目标阅读风格和 Astro 构建管线兼容。
- 排除：MathJax；自动给无编号公式编号。

## D-029：图名下置，表名上置

- 状态：Accepted
- 决策：保留原图表编号，不统一重编号。
- 原因：符合用户指定的出版习惯。

## D-030：支持教材语义容器

- 状态：Accepted
- 决策：definition、theorem、proof、example、exercise、solution、note、warning。
- 原因：教材结构需要统一视觉表达。
- 约束：未识别内容仍可按普通正文显示。

## D-031：目录需要自动候选 + 人工确认

- 状态：Accepted
- 决策：系统生成候选，管理员在预览中调整标题、层级、顺序和拆页。
- 原因：纯自动识别无法可靠覆盖所有 MinerU 输出。
- 排除：要求用户手写 YAML。

## D-032：默认按二级标题拆页

- 状态：Accepted
- 决策：存在二级标题时默认一节一页；短章或无二级标题时整章一页。
- 原因：兼顾语义链接、页面长度和 D2L 风格。

## D-033：阅读设置为全局默认 + 单书覆盖

- 状态：Accepted
- 决策：登录后跨设备同步。
- 原因：保持全局一致，同时允许特殊图书调整。

## D-034：每本书第一版固定一个 notes.md

- 状态：Accepted
- 决策：自由笔记和结构化批注分开存储，但可互相插入引用。
- 原因：避免与 Obsidian 集成和多笔记系统过早复杂化。

## D-035：Vditor 只用于 notes.md

- 状态：Accepted
- 决策：正文和只读展示仍使用统一 Markdown/HTML 管线。
- 原因：避免编辑器成为核心渲染依赖。

## D-036：首页只展示精选集合

- 状态：Accepted
- 决策：手动和自动书架均可隐藏、排序；提供“查看全部书库”。
- 原因：实体书架视觉不适合管理全部藏书。

## D-037：首页只参考 Twilight 视觉语言

- 状态：Accepted
- 决策：与 `mirawind.top` 保持相似设计，不引入博客业务。
- 原因：图书馆和博客职责独立，但品牌体验统一。

## D-038：书籍删除进入 30 天回收站

- 状态：Superseded by D-107
- 决策：立即隐藏，保留全部数据 30 天，可恢复或永久删除。
- 原因：降低误删风险，不引入复杂版本管理。

## D-039：备份不作为产品功能

- 状态：Accepted
- 决策：不做自动备份、异地同步或备份 UI。
- 原因：用户明确拒绝产品化备份。
- 约束：升级和卸载仍不得默认删除持久化数据。

## D-040：采用 Spec-Driven Development + Codex

- 状态：Accepted
- 决策：规格文档、Constitution、AGENTS.md、Skills、worktree 和自动测试指导开发。
- 原因：避免让 Agent 直接从长对话推断当前需求。

## D-041：复用成熟组件，避免从零实现基础设施

- 状态：Accepted
- 决策：Markdown、KaTeX、WebAuthn、灯箱、代码高亮等优先采用成熟库。
- 原因：控制复杂度和安全风险。
- 约束：完整书库应用只做研究参考，不直接 fork 为基础。

## D-042：首个垂直切片只做 MinerU 公开出版

- 状态：Accepted
- 决策：M1 只覆盖导入、安全校验、目录确认、语义 HTML、搜索和原子发布。
- 原因：优先验证项目最独特、风险最高的链路。
- 排除：EPUB、高亮、笔记、完整文件夹管理、Twilight 首页。

## D-043：M1 的 MinerU 导入单位为“一包一本书”

- 状态：Accepted
- 决策：每次导入只接受一个 MinerU ZIP，且该 ZIP 只对应一本书。系统递归发现 Markdown，并结合 MinerU Cloud `full.md`、MinerU CLI `<stem>.md`、相邻伴随文件和资源引用完整性识别主正文。只有一个无错误的高置信候选时自动选择；普通单 Markdown 必须由管理员确认；多个书籍 bundle 视为错误，要求拆包后重新上传。
- 原因：官方云端、CLI、FastAPI、Gradio 及不同 MinerU 版本的文件名和目录层级并不一致，不能依赖 ZIP 根目录、遍历顺序或文件大小猜测。
- 约束：Markdown 所在目录是相对资源解析基准，候选所属 bundle 是路径安全边界；标题、JSON 和图片均不是主正文存在的硬性条件。
- 调研依据：`docs/research/mineru-output-structure.md`。

## D-044：M1 不提供章节正文重排

- 状态：Accepted
- 决策：M1 保持 Markdown 正文顺序不变。管理员可以选择目录标题、设置显示标题、调整发布层级和确认拆页，但不能通过目录界面拖拽改变章节顺序。
- 原因：重排必须明确是只移动目录项还是连同章节正文、脚注和内部链接一起移动；在首个垂直切片中引入该能力会显著扩大内容编辑和链接修复范围。
- 处理：如果源顺序错误，管理员修改 Markdown 后重新导入。
- 范围：D-031 中的“调整顺序”不进入 M1，后续里程碑可另行评估。

## D-045：每本书必须以 `book.yaml` 管理可移植出版配置

- 状态：Accepted
- 决策：每本书必须具有版本化的 `book.yaml`，作为目录及其他可移植出版配置的权威来源。目录选择、显示标题、发布层级、拆页、内容角色、可选页面 alias 和编号策略均保存在其中。
- 原因：需要让人工确认结果可审计、可导出、可重新导入，并避免数据库与文件各自维护一份可独立编辑的目录配置。
- 约束：管理界面原子更新 `book.yaml`；数据库只保存派生索引或缓存。`book.yaml` 不保存正文、笔记、批注、书签、进度或其他私人数据。
- 一致性：Markdown 仍是唯一可编辑正文源；`book.yaml` 只对发布结构和展示行为施加配置覆盖。

## D-046：M1 只预留页面 alias，不提供编辑

- 状态：Accepted
- 决策：`book.yaml` 从第一版起保留可选页面 `alias` 字段，但 M1 管理界面不提供 alias 编辑。M1 阅读路由先使用稳定数字 `pageKey`。
- 原因：预留字段可以避免未来迁移数据模型，同时不把首个 MinerU 出版切片扩展为完整路由管理功能。
- 后续行为：未来设置 alias 后，数字地址重定向到当前别名规范地址。

## D-047：出版结构使用四类内容角色

- 状态：Accepted
- 决策：M1 允许管理员将顶层内容标记为 `frontmatter`、`body`、`appendix` 或 `backmatter`，并写入 `book.yaml`。子标题默认继承所属顶层内容的角色。
- 语义：
  - `frontmatter`：序言、前言、导读、符号表等正文前内容，不自动显示章节编号。
  - `body`：正式章节，使用正常章节编号和拆页规则。
  - `appendix`：附录内容，使用 `附录 A`、`A.1` 等独立编号。
  - `backmatter`：参考文献、索引、后记、致谢等正文后内容，不自动显示章节编号。
- 原因：四类内容的编号和出版语义不同，尤其附录不能等同于普通正文或后置内容。
- 约束：角色只影响编号、目录展示、语义和默认拆页，不移动 Markdown 内容；所有角色仍生成语义 HTML 并进入搜索。

## D-048：目录勾选只控制导航可见性

- 状态：Accepted
- 决策：取消勾选标题只使该标题不出现在全书目录和页面提纲中，不删除标题或其正文内容。
- 原因：目录编辑与正文编辑必须保持边界清晰，避免用户在导航配置中意外删除内容。
- 约束：未入目录的内容仍按 Markdown 原样发布、搜索并建立内部锚点；真正删除或隐藏正文必须修改 Markdown 后重新导入。

## D-049：标题重命名采用显示覆盖

- 状态：Accepted
- 决策：在目录预览中重命名标题时，不改写 Markdown，而是在 `book.yaml` 中保存 `display_title`。目录、阅读页标题、页面提纲和页面标题统一使用该显示值。
- 原因：既需要修正 MinerU 识别出的标题，又要保留原始 Markdown 以便追溯和重新导入。
- 约束：标题节点使用稳定 ID 关联；修改显示标题不得改变节点身份或破坏内部链接。

## D-050：配置层级决定最终发布结构

- 状态：Accepted
- 决策：调整标题层级时，在 `book.yaml` 中保存 `display_level`，不改写 Markdown。配置后的层级用于全书目录、页面提纲、自动编号和最终语义 HTML 的 `h1`–`h4`。
- 原因：MinerU 的标题级别可能识别错误，人工确认后的结构必须在导航和正文语义中保持一致。
- 约束：系统必须验证层级连续且结构有效，不能从一级直接跳到三级；调整父标题层级时其子树一起移动，但 Markdown 正文顺序保持不变。

## D-051：M1 只允许在标题节点前拆页

- 状态：Accepted
- 决策：M1 不支持在段落、公式、表格或图片中间任意插入分页点。系统生成默认拆页建议，管理员只能切换标题节点的 `starts_page`，结果写入 `book.yaml`。
- 原因：以标题作为页面边界可以保证每个内容块只属于一个页面，简化稳定 ID、内部链接、搜索定位和重新导入。
- 约束：拆页只改变发布页面边界，不改变 Markdown 正文顺序或内容。

## D-052：后台重建，前台始终读取已发布版本

- 状态：Accepted
- 决策：上传、重新导入或修改出版配置后，系统在后台构建 AST、HTML、资源映射和搜索索引。阅读请求只读取已经发布并校验完成的预生成版本，严禁在请求路径中执行 Markdown 解析、AST 构建、KaTeX 渲染、代码高亮或搜索索引生成。
- 原因：构建耗时不得转化为读者打开页面的等待时间。
- 发布行为：重建期间继续服务完整旧版本；新版本全部生成并校验成功后原子切换；构建失败时继续使用旧版本。
- 性能目标：单机且未命中公共缓存时，阅读页服务端响应时间 p95 不超过 300ms。M1 必须使用代表性的大型 MinerU ZIP 建立导入和重建基准。

## D-053：完整 AST 不持久化

- 状态：正文权威部分由 D-136 替代；解析器 AST 仍为瞬态数据
- 决策：Markdown 与 `book.yaml` 是唯一权威源。完整 AST 只在后台导入和发布编译期间生成，不作为长期保存或人工编辑的数据。
- 持久化产物：每个不可变书籍版本保存带 schema 版本的 `document-manifest.json`、预生成 HTML、资源映射和搜索索引。manifest 记录页面、稳定块 ID、源位置、文本指纹、资源映射和源文件哈希等重建与定位信息。
- 原因：避免维护第二份正文以及 AST 格式升级、数据库和文件同步问题；全部派生产物均可从 Markdown、`book.yaml` 和编译器重建。
- 性能：AST 重建只发生在后台发布流程，不进入阅读请求路径。

## D-054：稳定 ID 分配到块级内容

- 状态：Accepted
- 决策：所有可独立定位、搜索或批注的块级内容必须具有稳定 ID，包括标题、段落、列表项、引用、代码块、公式、图片、表格、脚注和教材语义容器。
- 排除：粗体、链接、行内代码、行内公式等行内内容不单独生成稳定 ID。
- 原因：搜索、书签、内部链接和未来批注需要定位到明确而适量的内容单元；为每个行内片段分配 ID 会造成不必要的复杂度和不稳定性。

## D-055：稳定块 ID 随机生成并在重新导入时可靠继承

- 状态：Accepted
- 决策：块在第一次导入时获得不含业务语义的随机稳定 ID。重新导入时，系统通过规范化内容指纹、相邻上下文和结构位置进行匹配；只有可靠匹配时才继承旧 ID。
- 行为：新增块生成新 ID；删除块的旧 ID 退休且永不复用；无法可靠匹配的块生成新 ID，相关批注进入待重新定位。
- 原因：标题、正文、路径或位置都可能变化；将这些值或文本哈希直接作为 ID 会使轻微修改改变块身份。
- 约束：不得为了提高继承率而进行宽松猜测或静默挂载。

## D-056：manifest 保留当前版本的 Markdown 源位置

- 状态：Accepted
- 决策：`document-manifest.json` 为每个块记录当前版本 Markdown 的源文件相对路径以及起止行号和列号。
- 用途：用于导入诊断、预览定位、错误提示和未来“在源文件中打开”能力。
- 约束：源位置只描述当前版本，不参与稳定 ID 生成或身份判断；重新导入后必须根据新 Markdown 重新计算。

## D-057：`book.yaml` 与 manifest 独立版本化

- 状态：Accepted
- 决策：`book.yaml` 和 `document-manifest.json` 分别具有独立的整数 `schema_version`，不得共用版本号。
- 原因：`book.yaml` 是长期保存、可导入导出的出版配置；manifest 是可以重新生成的内部发布产物，两者演进速度和兼容周期不同。
- 迁移：旧版本必须通过明确的迁移程序逐级升级，并在成功后原子替换；遇到高于当前程序支持范围的未知版本时拒绝发布并报告兼容性错误。
- 约束：不得静默忽略未知 schema 版本或猜测字段含义。

## D-058：精确高亮偏移规则推迟到 M3

- 状态：Accepted
- 决策：M1 只为块生成规范化可见文本和带版本的 `text_fingerprint`，用于搜索与重新导入匹配；不在 M1 定义或保存高亮选区的精确起止偏移。
- M1 规范化：基于渲染后可见文本，使用 Unicode NFC，并统一换行；不得将 Markdown 标记作为可见文本。
- 原因：高亮偏移必须结合真实浏览器 DOM、中文、KaTeX、行内代码、软换行和 React Island 边界验证，提前冻结容易造成错误锚点和后续迁移。
- 后续：OQ-012 和 OQ-013 在 M3 高亮开发前通过浏览器 PoC 冻结。

## D-059：M1 使用真实单管理员认证

- 状态：Accepted
- 决策：M0 接入成熟认证库、真实数据库 session、统一管理路由守卫、Passkey 和备用密码；M1 的上传、预览、发布及其他管理页面和 API 不允许使用开发模式绕过认证。
- 用户模型：系统只有唯一管理员，不提供公开注册入口；Passkey 是主要登录方式，密码只作为备用与恢复手段。
- 原因：如果首个垂直切片使用临时管理员模式，后续接入真实认证时需要重写并重新审计全部管理路由和 API 权限边界。
- 约束：WebAuthn 验证、session 和密码哈希必须复用成熟库，不自行实现认证协议。

## D-060：唯一管理员只能通过离线命令初始化

- 状态：Accepted
- 决策：首次管理员只能通过服务器终端的一次性离线命令创建。正式 Web 服务永久关闭注册，不提供网页注册、邀请或首次初始化入口。
- 初始流程：离线命令创建唯一管理员和备用密码；管理员首次使用密码登录，在已有真实 session 内登记 Passkey。
- 原因：避免在公网暴露可被抢占的首次初始化端点，同时保留可审计、可自动化的自托管部署流程。
- 约束：未认证状态不得登记 Passkey；系统不得根据“数据库中暂无用户”而自动开放网页注册。

## D-061：双凭据失效时只允许离线完全恢复

- 状态：Accepted
- 决策：当 Passkey 和备用密码均不可用时，只能通过服务器终端的离线恢复命令设置新密码。恢复操作必须撤销全部现有 session，并删除全部旧 Passkey；管理员随后使用新密码登录并重新登记 Passkey。
- 原因：管理员确认始终可以登录服务器，因此 M1 不引入邮件、短信或恢复码通道，减少攻击面和外部依赖。
- 约束：恢复能力不得通过 HTTP 或管理网页暴露；命令必须要求服务器主机上的管理权限，并留下不含凭据内容的审计记录。

## D-062：M1 不要求公开权利确认

- 状态：Accepted
- 决策：M1 将书籍切换为 `public` 时不显示权利确认操作，也不以权利声明阻断发布。
- 扩展点：发布应用层必须保留统一的发布前策略检查接口，M1 的默认策略允许发布；未来可在该接口加入权利确认、确认记录或其他发布政策，而不必重写发布流程。
- 约束：M1 不得伪造、预填或持久化一条并未由管理员作出的权利确认；预留接口不得在当前版本增加用户操作。

## D-063：M1 提供原文件下载

- 状态：Accepted
- 决策：M1 必须支持读者下载书籍对应的原文件，不能将 MinerU ZIP、PDF、EPUB 等原文件仅作为后台导入材料或管理员私有存档。
- 约束：下载必须由受控的应用路由提供，并使用安全的下载文件名和正确的响应头；不得直接暴露服务器存储路径。
- 待定：原文件下载与书籍公开状态的关系，以及新书默认是否开放下载，继续单独确认。

## D-064：原文件下载权限跟随书籍公开状态

- 状态：Accepted
- 决策：M1 不设置独立的原文件下载开关。书籍为 `public` 时，其登记为原文件的 MinerU ZIP、PDF、EPUB 等文件允许公开下载；书籍为 `draft` 或 `private` 时，仅管理员可以下载。
- 原因：下载能力是公开书籍的一部分，避免 M1 再引入一套容易配置不一致的可见性状态。
- 约束：公开下载范围仅包含该书明确登记的原文件，不包含系统生成的 `book.yaml`、`document-manifest.json`、搜索索引、私人笔记、批注、临时文件或服务器路径中的其他内容。

## D-065：MinerU ZIP 上传上限为 2 GiB

- 状态：Accepted
- 决策：M1 单次上传的 MinerU ZIP 最大体积为 2 GiB。
- 实现：服务端必须流式接收并在读取过程中累计字节数；超过上限时立即终止上传，返回明确的限制错误，并删除未完成的临时文件。
- 约束：不得为了判断体积而将整个上传读入内存；反向代理和应用层的请求体限制必须一致，且均不得低于或绕过该产品限制。

## D-066：MinerU ZIP 解压总量上限为 8 GiB

- 状态：Accepted
- 决策：M1 单次导入解压后的全部文件实际总大小不得超过 8 GiB。
- 实现：解压器必须按实际写出的字节数累计并强制执行限制，不得只信任 ZIP 条目声明的未压缩大小；超过上限时立即停止解压，将导入标记为失败并清理整个暂存目录。
- 约束：不完整的解压结果不得进入预览、发布目录或原文件下载范围。

## D-067：MinerU ZIP 条目总数上限为 20,000

- 状态：Accepted
- 决策：M1 单个 MinerU ZIP 最多包含 20,000 个文件和目录条目。
- 计数：目录、空文件、隐藏文件以及最终不会被导入器使用的条目都计入上限，不能通过文件类型过滤规避限制。
- 实现：扫描 ZIP 中央目录时和流式解压时都必须校验条目数量；超限后整次导入失败并清理暂存内容。

## D-068：单个解压文件上限为 2 GiB

- 状态：Accepted
- 决策：M1 的 MinerU ZIP 中，任何单个解压文件的实际大小不得超过 2 GiB。
- 原因：在 8 GiB 总预算内保留大型原始 PDF 等文件的兼容性，同时避免单个条目独占全部解压空间。
- 实现：解压器必须按实际写出的字节数执行限制，不得只信任 ZIP 条目声明的大小；任一文件超限后整次导入失败并清理暂存目录。
- 后续：需要进入 Markdown、图片等解析器的文件还应执行更严格的类型专用限制。

## D-069：主 Markdown 解析上限为 256 MiB

- 状态：Accepted
- 决策：M1 的单个候选主 Markdown 实际大小不得超过 256 MiB。
- 行为：超过上限的候选不得进入 Markdown 解析、AST 构建或目录预览；如果它是唯一或已确认的主文档，整次导入失败并明确提示“主文档超过解析上限”。
- 约束：该专用限制不影响只以流式方式保存和下载的原始 PDF 等文件；解析实现仍必须避免不必要的全文副本和无界并发。

## D-070：单张图片限制为 1 亿像素

- 状态：Accepted
- 决策：M1 导入的单张图片总像素数不得超过 100,000,000，任一边长度不得超过 32,768 像素。
- 实现：图片处理前先读取并验证可信的图片头信息；超限图片不得进入完整解码、缩放或发布流程，整次导入失败并报告具体文件。
- 原因：防止压缩体积很小但解码后占用巨量内存的图片拖垮后台任务。

## D-071：ZIP 内目录深度上限为 20 层

- 状态：Accepted
- 决策：M1 的 ZIP 条目路径最多允许 20 层目录；从压缩包根目录开始计算目录组件，常见的最外层书名包装目录也计入。
- 行为：任何条目超过目录深度上限时，整次导入失败并报告对应的安全显示路径。
- 约束：目录深度必须在路径规范化和安全校验后统一计算，不得通过重复分隔符、`.` 或平台特有分隔符绕过。

## D-072：单个路径组件上限为 255 个 UTF-8 字节

- 状态：Accepted
- 决策：ZIP 条目中的每个文件名或目录名组件解码为 UTF-8 后不得超过 255 字节。
- 行为：任何组件超限时整次导入失败；系统必须报告对应路径，但不得自动截断、改名或继续发布。
- 原因：保持与常见服务器文件系统限制兼容，同时避免自动改名破坏 Markdown 中的资源引用。

## D-073：ZIP 内完整相对路径上限为 2,048 个 UTF-8 字节

- 状态：Accepted
- 决策：路径规范化后的 ZIP 条目完整相对路径不得超过 2,048 个 UTF-8 字节。
- 原因：为服务器上的存储根目录、书籍 ID 和版本目录前缀保留空间，避免接近文件系统的整体路径限制。
- 行为：任何条目超过完整路径上限时整次导入失败，不得通过散列改名或静默跳过该条目。

## D-074：后台导入或重建任务最长执行 30 分钟

- 状态：Accepted
- 决策：M1 的单次后台导入或重建任务最长执行时间为 30 分钟，从上传完成且任务开始运行时计时，不包含用户上传耗时和队列等待时间。
- 行为：任务超时后必须终止其工作进程，标记为失败并清理所有未发布产物；当前已发布版本继续提供服务。
- 约束：超时任务不得原子切换为当前版本；错误信息和任务日志必须明确区分超时、资源超限与内容解析失败。

## D-075：ZIP 最大解压倍率为 200:1

- 状态：Accepted
- 决策：M1 同时检查单个 ZIP 文件条目和整个 ZIP 的解压倍率，倍率按“实际解压字节数 ÷ 对应压缩数据字节数”计算。当对应的未压缩数据不超过 64 MiB 时不执行倍率限制；超过 64 MiB 后，倍率不得高于 200:1。
- 澄清：64 MiB 只是倍率检查的起算门槛，不是文件或整包的解压上限；8 GiB 解压总量和 2 GiB 单文件上限仍独立生效。例如 1 MiB 压缩数据解压为 200 MiB 可以，解压为 500 MiB 则拒绝。
- 原因：防止体积很小的 ZIP 在达到 8 GiB 总量上限前仍迫使服务器执行大量解压和写盘，同时避免误伤体积很小但高度可压缩的正常文本。
- 实现：预扫描声明值用于尽早拒绝明显异常包，流式解压时再按实际读取和写出的字节数执行最终限制；任一层级超限后整次导入失败并清理暂存目录。

## D-076：SQLite 是当前发布版本的唯一权威指针

- 状态：Accepted
- 决策：每本书的 SQLite `current_version_id` 是当前已发布版本的唯一权威指针。文件系统只保存按 `version_id` 命名的不可变版本目录，不维护 `current` 软链接、可变当前目录或第二份当前版本指针。
- 读取：阅读请求先取得一次 `current_version_id`，随后在该请求内始终读取对应的不可变版本目录，不得中途重新解析当前版本。
- 原因：避免数据库指针与文件系统指针分叉；发布切换只需依赖 SQLite 的原子事务。

## D-077：单书发布采用文件先固化、数据库后切换的两阶段协议

- 状态：Accepted
- 存储：每本书使用同一文件系统内的 `staging/<job_id>/` 和不可变 `versions/<version_id>/`。版本目录包含 `book.yaml`、`document-manifest.json`、HTML、资源、原文件和 `version.json`，进入 `versions/` 后不得原地修改，也不得放入 Astro `public/`。
- 构建锁：同一本书同时只允许一个发布任务。任务捕获构建开始时的 `current_version_id` 和配置修订号；最终切换时必须再次比较，防止过期任务覆盖较新的正文或配置。
- 文件阶段：在 staging 中完成解压、编译、FTS 待写数据生成、引用校验、schema 校验和哈希校验；全部文件及目录持久化后，将 staging 在同一文件系统内原子重命名为 `versions/<version_id>`，再同步父目录。此时版本仍不公开。
- 数据准备阶段：在 SQLite 事务中写入状态为 `ready` 的版本记录和带 `version_id` 的全部 FTS5 行，并校验索引条数、块 ID 和摘要。FTS5 写入或校验失败必须整体回滚并阻止发布。
- 切换阶段：通过一个短 `BEGIN IMMEDIATE` 事务再次核对旧 `current_version_id`、配置修订号和新版本 `ready` 状态，然后原子更新 `books.current_version_id`、新旧版本状态和任务状态。提交前读者只见旧版，提交后新请求只见新版。
- 读取一致性：阅读请求只解析一次当前版本；HTML 内部资源 URL 必须带版本 ID 或内容哈希。公开搜索必须按 `books.current_version_id` 过滤 FTS5。旧版本资源仅在该书当前仍公开且该版本曾成功发布时可公开访问；书籍改为私人后所有历史版本立即停止公开访问。
- 故障语义：构建、校验、FTS 或切换失败均保留旧版。重命名后但数据库登记前崩溃只产生未引用目录；数据库已记录 `ready` 但尚未切换时不得自动公开；SQLite 切换事务崩溃时结果只能全旧或全新。
- 启动恢复：启动时清理无存活任务的过期 staging，识别并隔离孤立版本，检查数据库记录缺失文件的损坏情况，并快速验证当前版本的 `version.json`、manifest 和关键文件；完整哈希审计在后台运行。孤立版本隔离 24 小时后清理，绝不自动发布。
- 降级恢复：当前版本损坏时，通过 SQLite 事务自动回退到最近一个校验通过的已发布版本并记录严重错误；无可回退版本时仅该书返回 `503`，不得拖垮其他书籍或管理后台。
- 回收：发布事务不删除旧版本。M1 始终保留当前版本和上一个成功发布版本；更早版本至少等待 24 小时后由独立任务连同对应 FTS5 记录清理。清理失败只告警，不得改变发布结果。

## D-078：阅读资源与原文件下载使用不同的浏览器缓存规则

- 状态：Accepted
- 阅读资源：公开书籍的版本化图片等阅读资源返回 `Cache-Control: private, max-age=31536000, immutable`。资源仍可公开访问，但只允许最终用户浏览器缓存一年，不允许 CDN 或其他共享缓存保存；版本变化必须产生新 URL。
- 原文件下载：公开 PDF、EPUB、MinerU ZIP 等原文件下载返回 `Cache-Control: private, no-store`，避免浏览器 HTTP 缓存额外保存大型文件；用户主动保存的下载文件不受影响。
- 私有化语义：书籍改为私人后，服务器立即拒绝新的未认证访问。已经在公开期间交付给读者并保存在浏览器缓存或磁盘中的副本无法被系统收回。
- 站点静态资源：带内容哈希的网站 JS、CSS 和字体不含书籍或私人数据，可以单独使用公共长期 immutable 缓存。

## D-079：公开 HTML 必须保存后逐次重新验证

- 状态：Accepted
- 决策：公开 HTML 返回 `Cache-Control: public, max-age=0, must-revalidate`，并提供由当前版本、具体路由和渲染器版本共同决定的强 ETag。
- 行为：缓存可以保存响应，但每次复用前必须向源站验证；内容未变化时返回 `304 Not Modified`，发布新版或改为私人后立即返回新表示或拒绝访问。
- 隐私：可被公共缓存保存的 HTML 必须对所有访客完全相同，不得包含管理员身份、私人阅读状态、管理操作或其他用户特有数据；这些能力通过独立的私有 API 加载。
- 原因：保留条件请求的带宽收益，同时不允许短期陈旧缓存延迟发布更新或私有化。

## D-080：路由映射、跳转和 404 不得形成陈旧缓存

- 状态：Accepted
- 内容响应：alias 地址和直接内容地址采用相同的公开 HTML 重新验证策略；强 ETag 必须包含实际请求路由，防止不同地址的表示互相串用。
- 跳转响应：数字地址跳转到当前 alias 时返回 `Cache-Control: no-store`，不得让浏览器或共享缓存长期记住可能变化的 alias 映射。
- 不存在路径：不存在、已移走、已私有化或无权访问地址的 `404` 返回 `Cache-Control: no-store`，确保旧路径可以立即重新使用且不会泄露资源状态。
- 约束：旧 alias 和旧文件夹路径仍遵循 D-008，不保留重定向。

## D-081：所有非公开和管理响应禁止存储

- 状态：Accepted
- 决策：`draft`、`private` 正文、图片、搜索和附件，登录与管理页面，以及管理 API 和其他私人 API，统一返回 `Cache-Control: private, no-store`。
- 错误响应：`401`、`403` 以及用于隐藏私人资源存在性的 `404` 同样不得存储；匿名访问私人资源继续返回不缓存的 `404`。
- 原因：避免退出登录、权限变化或切换设备后从浏览器、代理或共享缓存重新取得私人内容。

## D-082：后台任务使用独立 worker 和 SQLite 持久化队列

- 状态：Accepted
- 进程模型：M1 在同一代码库和同一部署中运行一个 Astro Web 进程与一个独立 worker 进程。Web 进程只负责流式上传、入队、状态查询和发布控制，不执行大型 ZIP 解压、Markdown 编译或索引构建；不引入 Redis、BullMQ 或外部队列。
- 并发：M1 全局同时只执行一个导入或重建任务。worker 通过 SQLite 原子领取任务，每 10 秒更新一次租约心跳；60 秒没有心跳时任务视为中断。
- 隔离：每个任务在可终止的子进程中执行；达到 D-074 的 30 分钟上限时终止整个任务进程树，并清理未发布产物。
- 恢复：worker 或服务器中断后，失去租约的运行任务标记为 `interrupted` 并清理不完整 staging。仅由 worker 崩溃或服务器重启造成的中断可从保留的原始 ZIP 自动重新执行一次；资源超限、内容错误或第二次中断不自动重试。
- 发布边界：已经构建为 `ready` 但尚未发布的版本绝不自动公开，仍须由管理员重试发布。任务状态统一为 `queued`、`running`、`succeeded`、`failed`、`canceled` 和 `interrupted`。

## D-084：原文件采用安全、可续传且禁止索引的下载协议

- 状态：Accepted
- 文件名：下载响应使用 `Content-Disposition: attachment`。名称以书籍显示标题和真实扩展名生成，例如 `书名.pdf`、`书名.epub`、`书名-mineru.zip`；同时提供 UTF-8 `filename*` 与 `book-<book_id>.<ext>` ASCII 回退名。生成名称必须去除路径分隔符、控制字符和其他危险字符，不修改服务器上的原文件名。
- 响应：返回正确的 `Content-Type`、`Content-Length`、`X-Content-Type-Options: nosniff`、`Accept-Ranges: bytes` 和基于文件哈希的强 ETag，支持 Range 请求与断点续传，并继续使用 D-078 的 `Cache-Control: private, no-store`。
- 权限：每次完整下载和 Range 请求都必须重新检查书籍当前权限，不得依赖不可猜测 URL 或直接暴露存储路径。M1 将上传的 MinerU ZIP 登记为可下载原文件；以后登记的 PDF 和 EPUB 沿用同一协议。
- 搜索引擎：下载响应返回 `X-Robots-Tag: noindex, nofollow, noarchive, nosnippet`，页面下载链接使用 `download` 和 `rel="nofollow"`。

## D-093：`version.json` 使用独立的严格 v1 完整标记格式

- 状态：Accepted
- 决策：每个完成的不可变版本目录必须包含规范 JSON `version.json`，其独立 `schema_version` 在 M1 为 `1`，并且 `complete` 必须严格为 `true`。它记录 `book_id`、`version_id`、`source_id`、`config_revision`、可空的前一版本 ID、冻结的 UTC `created_at`、编译器/渲染器/文本规范化身份、`book.yaml` 与 `document-manifest.json` 的 SHA-256，以及版本目录内除 `version.json` 自身之外每个文件的相对路径、字节数和 SHA-256。
- 原因：恢复、发布 compare-and-swap、快速启动校验和同版本可复现构建需要一个不依赖 SQLite 当前指针的自描述完整标记；排除自身哈希可以避免递归定义，同时完整文件清单仍能验证目录闭包。
- 严格性：v1 拒绝未知字段、重复文件路径、绝对/反斜杠/遍历路径、缺失关键文件、清单外文件、哈希不符、身份不一致、`complete != true` 和高于当前支持范围的 schema。写入 `version.json` 是 staging 的最后一个文件步骤；只有随后完成文件与目录 fsync、同文件系统 rename 和父目录 fsync，版本才有资格登记为 `ready`。
- 演进：`version.json`、`book.yaml` 与 `document-manifest.json` 三者独立版本化。未来格式变更必须新增版本决策、fixture 和兼容性测试；不得静默忽略未知新版本。旧版本迁移只能创建新的完整目录并原子替换，不能原地修改已发布目录。

## D-104：中文混排器在接纳正文前执行并持久化规范化 Markdown

  阅读、搜索或编辑。发布时规范化 Markdown 随新不可变版本冻结。
- 配置与兼容：`book.yaml` v2 在 `source.preprocessing.typography` 记录应用过的
  profile、输入/输出摘要和有界统计。profile 取 `verbatim-v1` 或 `zh-smart-v1`。现有
  v1 配置迁移时记录 `verbatim-v1` 且输入/输出摘要相同，避免旧书无意变化；新导入默认
  使用 `zh-smart-v1`。
- `zh-smart-v1` 规则：在中文与拉丁字母或阿拉伯数字的直接边界保留且规范为一个 ASCII
  空格；把中文语境中的 ASCII 逗号、分号、冒号、问号、叹号、句末句点、成对括号、
  成对双引号和三点省略号转换为对应中文全角形式，并清理中文标点内侧多余空格。转换
  必须确定、幂等，且不改变段落或显式换行。
- 保护边界：代码块、行内代码、公式、原始 HTML、链接目的地址以及被识别为 URL、
  邮箱、文件路径、文件名、版本号、时间、十进制数、千位分隔数、ISBN/DOI 等技术
  token 的内容不参与转换。链接可见文字只有在不是技术 token 时才按普通文本处理。
- 改写方式：解析 Markdown 只用于确定可改写 text slice 和保护上下文，实际输出按原始
  UTF-8 字节范围做最小、非重叠替换，不用 AST 全量重新序列化。这样除目标空格和标点外
  的 Markdown 语法、换行和源格式保持不变。
- 执行顺序：排版输出成为后续印刷目录识别、UTF-8 字节范围、标题匹配、可见文本指纹、
  目录、页面、HTML、搜索和语义摘要的共同输入。所有源摘要和范围都绑定规范化输出，
  不绑定预处理前的临时文本。
- 可观察性：管理预览显示所用 profile、输入/输出摘要、插入或规范空格数、标点转换数

  指标数据库或新的运行服务。
- 格式切换：worker health 是可删除派生状态，直接切换到严格 v2。Web 对旧的无版本格式、未知更新

  attempt 状态原子重建 v2，不迁移或猜测旧字段。观测采样、序列化或 health 文件写入失败不得改变
  任务、租约、终态或当前出版版本，只记录安全 warning 并在下次有界刷新重试。

  `max(5%, 1 s)` wall 与 `max(5%, 64 MiB)` RSS 回退容差，Reader/Search 并发门禁与 reference

## D-137：IR 工作稿可修改，以最后修订时间作为唯一修订标识

- 状态：Accepted（IR 设计约定；运行时切换尚未实施）
- 日期：2026-09-07
- 决策：当前工作稿保存在可更新的 `book.json`；正文、元数据、出版设置与顶层 `updated_at`
  一起原子保存。`updated_at` 同时表示最后修订时间和保存冲突标识，不另设整数 `revision`，
  不在 SQLite 中维护第二份权威草稿修订号。`schema_version` 仍独立表达格式版本。
- 生成：`updated_at` 使用服务端生成的 Unix 毫秒整数；首次接纳使用当前服务端时间，后续
  每次接受修改使用 `max(now_ms, previous_updated_at + 1)`。同毫秒保存及系统时钟回拨时
  仍严格递增；不保证始终精确等于实际墙上时间，不取文件 `mtime` 或客户端时钟。
- 保存：客户端提交 `expected_updated_at`。服务端在所有写入者共用的按书串行边界内比较
  当前值、校验修改并原子替换完整工作稿；过期保存不得覆盖。缺失、非法或超出可表示范围的
  时间值拒绝。仅本地编辑、预览、发布或权限变更不更新正文时间；无内容或设置变化不推进时间。
- 重导入与恢复：对已有图书接纳重导入或恢复内容时，继续从当前 `updated_at` 推进，不沿用
  导入包或旧快照的时间；对新图书由服务端初始化。不能通过回填旧时间让已过期的编辑重新有效。
- 预览与发布：构建时捕获一致的工作稿及资源快照，候选记录其 `source_updated_at`。构建期间
  可继续修改工作稿；发布必须在与保存共用的按书串行边界内确认候选时间等于当前工作稿时间，
  并核对冻结构建身份后切换发布指针。该时间只证明来源匹配，不能替代产物完整性校验。
- 历史：不可变要求适用于构建输入快照、ready candidate 和已发布版本，不要求每次保存都
  长期保留整书快照。编辑历史与撤销按独立功能定义；文件先持久化再原子替换，保存与任务登记
  之间的崩溃通过工作稿及任务状态核对恢复，不能假设文件系统与 SQLite 是同一个事务。
- 替代：本决策细化 D-136 的“一致修订”，替代 IR 设计提案中的不可变草稿修订、独立递增
  修订号和 SQLite 草稿修订权威。D-121、D-130 对切换前 Markdown/config revision 的实现
  约定不延续到新 IR；已发布不可变、单 worker、后台构建、授权与旧候选拒绝要求继续有效。
- 证据：IR 接入前验证同毫秒、时钟回拨、两个过期标签页、重导入与恢复、原子替换失败、
  替换后任务登记失败、构建期间编辑和发布与保存竞态。此次不修改现有 schema 或图书数据。
